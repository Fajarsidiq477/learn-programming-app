Variables

A variable is how your app remembers something.

What is a variable?

Think of a variable as a box with a label on it. The label is the variable's name, and the thing inside the box is its value. Your app can look inside the box at any time, and it can swap the content for something new.

Without variables an app forgets everything immediately. A game could not keep the score, a quiz could not count correct answers, and a login screen could not remember who you are.

Where to find the blocks

Open the Blocks view, then click Built-in → Variables. All variable blocks are orange.

The three things you do with a variable

1. Create it (initialize)

This block creates the box, gives it a name and puts a first value inside. Click the word name on the block and type your own name.

initialize global score to 0

This block stands alone on the workspace. It does not go inside any other block.

2. Read it (get)

The get block looks inside the box and gives you the value. It does not change anything.

get global score

3. Change it (set)

The set block throws away the old value and puts a new one in the box.

set global score to 10

Shortcut: hover your mouse over the variable's name in the initialize block. The matching get and set blocks pop up, ready to drag.

Example: a score counter

The app has one button and one label. Every time the button is clicked, the score goes up by 1 and the label shows the new score.

initialize global score to 0
when Button1 .Click
do
set global score to get global score + 1
set Label1 . Text to join " Score: " get global score

Read the first line inside the button like this: “take the current score, add 1, and store the result back in score.” Here is what happens when the button is clicked three times:

Global and local variables

GlobalLocal
Where it works Everywhere on the screen: in every event and every procedure. Only inside the block where it was created.
How long it lives As long as the screen is open. Only while that block is running.
Use it for Things the whole app must remember, like the score. A temporary value for one small calculation.

A local variable looks like this. The name total can only be used inside the in part:

initialize local total to 80 + 90
in
set Label1 . Text to get total

Rules for good names

  • Use a name that says what is inside: score is better than x.
  • No spaces. Write playerName or player_name.
  • Start with a letter, not a number.
  • Every global variable needs a different name.

Common mistakes

  • Putting initialize global inside an event. It must stand alone on the workspace.
  • Forgetting to update the label. Changing a variable does not change the screen. You must also set the label's text.
  • Using set score to 1 instead of set score to score + 1. The first one always makes the score 1. The second one adds 1.
  • Mixing up text and numbers. The text block "abc" cannot be used in a calculation.

Check your understanding

1. What is the difference between get and set?

get only reads the value. set replaces the value with a new one.

2. score is 5. The app runs set score to score + 2 two times. What is the value now?

9. First 5 + 2 = 7, then 7 + 2 = 9.

3. You need the player's score on every button of the screen. Global or local?

Global, because many different events need to use it.

4. Which type of value would you use to store whether the sound is on or off?

A boolean: true for on and false for off.
